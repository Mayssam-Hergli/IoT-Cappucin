## Hardware (Arduino IDE, ESP32 Dev Module)
Libraries: **DHT sensor library** (Adafruit) + Adafruit Unified Sensor, **ESP32Servo**, **ArduinoJson 7**. Check the ESP32 core version in Boards Manager: core 3.x uses `ledcAttach(pin, freq, res)` / `ledcWriteTone(pin, f)`, core 2.x uses channels (`ledcSetup`, `ledcAttachPin`).

| Part | ESP32 pin | Wiring notes |
|---|---|---|
| Gas sensor (MQ) AO | GPIO 34 | Sensor VCC = 5 V (VIN). AO can reach 5 V → divider: AO → 10 kΩ → GPIO34 → 20 kΩ → GND. Add 100 kΩ GPIO34 → GND so an unplugged sensor reads ~0 (fault detection). |
| DHT22 data | GPIO 4 | 3.3 V. Module usually has its pull-up. Read at most every 2 s. |
| LDR | GPIO 35 | 3.3 V → LDR → GPIO35 → 10 kΩ → GND. (If we got the IR obstacle sensor instead: see "No LDR" below.) |
| IR obstacle OUT (if fitted) | GPIO 33 | 3.3 V. OUT = LOW when something is in front. Used as anti-masking ("detector covered"). |
| Buzzer | GPIO 25 | Find out: active (on/off only) or passive (tones). |
| LED green / yellow / red | 26 / 27 / 14 | Each through 220 Ω to GND. |
| Servo (gas valve) | GPIO 18 | Power from 5 V (VIN), **shared GND**. 0° = open, 90° = closed. |
| Button | GPIO 13 | To GND, `INPUT_PULLUP`. Silence 60 s, never reset. |

GPIO 34/35 are ADC1, so they still work with Wi-Fi on. Power the gas sensor as early as possible (warm-up 20+ min). If the board resets when the servo moves, power the servo from a separate 5 V source with shared GND.

## Firmware structure (one sketch, several tabs)
- `ember_esp32.ino` — setup, the 500 ms tick, decision logic, actuators.
- `model.h` — generated by `train.py` (start with a placeholder: `MODEL_READY 0` → use rules).
- `ember_link.h` — from Israa. Until it arrives, compile with `#define USE_LINK 0`.

### Sampling (non-blocking, `millis()` timers)
- **LDR fast:** every 20 ms (50 Hz) `analogRead(35)` → accumulate sum, sum², n for the current 500 ms tick → `ldr_mean_tick`, `flicker_tick = std`.
- **Gas:** each tick, average 8 `analogRead(34)` → `gas_tick`.
- **DHT22:** every 2 s, hold the last valid temp/hum.
- Ring buffers of the last **10 ticks (= 5 s window)**: gas, temp, ldr_mean, flicker.

### The 5 features (computed every 500 ms over the 10-tick window)
| Feature | Definition |
|---|---|
| `gas_delta` | mean(gas window) − `gas_base` |
| `gas_slope` | (mean of ticks 7..9 − mean of ticks 0..2) / 3.5 s |
| `temp_slope` | (temp at tick 9 − temp at tick 0) / 4.5 s, in °C/s |
| `light_delta` | mean(ldr window) − `ldr_base` |
| `flicker` | mean(flicker window) |

Baselines: `gas_base` and `ldr_base` = mean of the first 40 ticks (20 s) after boot; afterwards update slowly (`base += 0.002 × (value − base)`) **only while level is NORMAL**. Features are "not ready" (level stays NORMAL, `mode` = rules) until the window and baselines are filled.

**No LDR?** Force `light_delta = 0` and `flicker = 0` (keep 5 features so all code stays the same; the model learns ~0 weight for them).

### Model inference (logistic regression, 3 classes in this order: normal, leak, fire)
`model.h` provides `FEAT_N 5`, `CLASS_N 3`, `FEAT_MEAN[5]`, `FEAT_SCALE[5]`, `W[3][5]`, `B[3]`, `MODEL_READY`.
```cpp
void predict(const float x[FEAT_N], const bool missing[FEAT_N], float probs[CLASS_N], float xs[FEAT_N]) {
  for (int j = 0; j < FEAT_N; j++) {
    xs[j] = missing[j] ? 0.0f : (x[j] - FEAT_MEAN[j]) / FEAT_SCALE[j];   // missing = faulty sensor → training mean
    xs[j] = constrain(xs[j], -10.0f, 10.0f);
  }
  float z[CLASS_N], zmax = -1e9;
  for (int k = 0; k < CLASS_N; k++) {
    z[k] = B[k];
    for (int j = 0; j < FEAT_N; j++) z[k] += W[k][j] * xs[j];
    zmax = max(zmax, z[k]);
  }
  float s = 0;
  for (int k = 0; k < CLASS_N; k++) { z[k] = expf(z[k] - zmax); s += z[k]; }
  for (int k = 0; k < CLASS_N; k++) probs[k] = z[k] / s;
}
// why[j] = W[c][j] * xs[j], with c = class behind the current cause (fire if none)
```
Then camera fusion and level logic exactly as in the contract (section 3).

### Fallback rules (`mode = "rules"`, used until the model is trained or if it misbehaves)
Constants to calibrate on the real sensors: `GAS_LEAK_TH` (gas_delta), `TEMP_SLOPE_TH` (°C/s), `FLICKER_TH`.
- fire if `flicker > FLICKER_TH` and (`temp_slope > TEMP_SLOPE_TH` or `gas_delta > GAS_LEAK_TH / 2`) → p_fire = 0.9
- else leak if `gas_delta > GAS_LEAK_TH` → p_leak = 0.9
- else normal.

### Actuators per level
| Level | LEDs | Buzzer | Valve |
|---|---|---|---|
| NORMAL | green steady | off | unchanged |
| WARNING | yellow blink 2 Hz | 100 ms beep every 1 s | **closes** if cause = gas_leak |
| ALARM | red strobe 5 Hz | gas: hi-lo two-tone · fire: rising sweep (active buzzer: fast vs slow on/off patterns) | **closes** |

- The valve never reopens by itself: only the `valve_open` command does.
- Button or `silence` command → buzzer off for 60 s. It never clears the latch.
- `reset` command → clears the ALARM latch (re-alarms after 1 s if the condition is still there).
- Link lost (`linkOk()` false for 3 s) → keep deciding alone, cv = 0, close the valve.

### Faults and tamper (jury will unplug a sensor)
- **dht:** `isnan()` 3 reads in a row.
- **gas:** raw ≤ 20 or ≥ 4080 for 5 s, or perfectly flat (std = 0) for 10 s.
- **ldr:** raw ≤ 5 or ≥ 4090 for 10 s.
- On fault: add the name to `faults`, mark its features `missing` (scaled value 0), a short chirp every 10 s. A fault must **never** start an alarm by itself.
- **tamper** (IR fitted): OUT LOW for more than 5 s → `tamper = true`.

### Each tick (500 ms)
1. Compute features → `predict` (or rules) → fusion → level logic → actuators.
2. Build the payload JSON (contract section 1) with ArduinoJson → `linkPublish(payload)` (non-blocking).
3. Read verified commands: `while (linkNextCommand(&id, &cmd))` → execute, store `last_cmd = id`.
4. Print one CSV line for recording:
```
DATA,<up_ms>,<gas_raw>,<temp>,<hum>,<ldr_raw>,<gas_delta>,<gas_slope>,<temp_slope>,<light_delta>,<flicker>,<level>
```
Serial at 115200 baud. Other debug lines must not start with `DATA,`.

## Shared contract (identical in all four files — do not change without telling the team)

### Network
- All devices on one **phone hotspot, 2.4 GHz** (the ESP32 cannot join 5 GHz). SSID `EMBER-NET`, password: *fill in*.
- Server = Israa's laptop. `SERVER_IP` = its IP on the hotspot (`ipconfig`). Allow Python through the Windows firewall (Private networks).
- `USE_TLS = true` → `https://SERVER_IP:5443` (self-signed certificate; clients skip certificate verification because the HMAC proves who sent each message). Fallback `USE_TLS = false` → `http://SERVER_IP:5000`. Everyone uses the same setting.
- Shared secret `EMBER_KEY` = 32 hex characters generated by Israa: `python -c "import secrets;print(secrets.token_hex(16))"`. Never in slides or screenshots.

### Envelope (every message, both directions)
```json
{"p": "<payload serialized as a JSON string>", "sig": "<lowercase hex HMAC-SHA256(EMBER_KEY, p)>"}
```
- The signature covers the **exact bytes of the string `p`**. The receiver verifies first (constant-time compare), then parses `p`.
- Bad signature → ignored, logged as REJECTED.

### 1) ESP32 → server: `POST /api/reading` every 500 ms
Payload `p`:
```json
{
  "dev": "room1", "boot": 48213, "seq": 42, "up_ms": 21000, "sim": false,
  "raw":  {"gas": 1830, "temp": 24.6, "hum": 41.0, "ldr": 2100, "ir": 1},
  "feat": {"gas_delta": 120.0, "gas_slope": 15.2, "temp_slope": 0.02, "light_delta": -30.0, "flicker": 4.1},
  "cv": 0.0,
  "probs": {"normal": 0.97, "leak": 0.02, "fire": 0.01},
  "why":  {"gas_delta": 0.4, "gas_slope": 0.1, "temp_slope": 0.0, "light_delta": 0.0, "flicker": 0.0},
  "level": 0, "state": "NORMAL", "cause": "none",
  "mode": "model", "latched": false, "silenced": false, "valve": "open",
  "faults": [], "tamper": false, "link_ok": true, "last_cmd": 0
}
```
- `level`: 0 = NORMAL, 1 = WARNING, 2 = ALARM. `state`: same as text. `cause`: `"none"` | `"gas_leak"` | `"fire"`.
- `probs.fire` is the value **after** camera fusion. `why` = contribution of each feature to the class behind the current cause (fire if none).
- `mode`: `"model"` (logistic regression) or `"rules"` (fallback). `faults`: any of `"gas"`, `"dht"`, `"ldr"`. `tamper`: IR sensor covered > 5 s (if fitted).
- `boot` = random number picked at each ESP32 boot. `seq` +1 each packet. Server rejects `seq` ≤ last seq of the same boot (replay).
- `last_cmd` = id of the last command the board executed (works as the ACK).
- `sim: true` only from `fake_esp32.py`; the dashboard then shows a SIMULATION banner.

Server reply (HTTP 200), same envelope, payload:
```json
{"ok": true, "cv": 0.82, "cv_fresh": true, "cmds": [{"id": 941234567, "cmd": "reset"}]}
```
- `cmd` ∈ `"reset"` | `"silence"` | `"valve_open"` | `"valve_close"`.
- `id` = `max(last_id + 1, int((time.time() - 1_700_000_000) * 10))`: always increasing, fits in 32 bits. The board runs a command only if the signature is valid **and** `id` > last executed id. The server re-sends a command until the board's `last_cmd` ≥ its id.
- `cv` = latest camera flame score 0..1. `cv_fresh` = camera posted less than 2 s ago.
- 401 = bad signature. 409 = replayed seq.

### 2) Camera → server: `POST /api/cv` every ~300 ms
Payload `p`:
```json
{"src": "cam1", "seq": 101, "score": 0.82, "flame": true, "boxes": [[120, 80, 60, 90]], "fps": 14.2, "jpg": "<base64 JPEG 320x240, annotated>"}
```
Reply: `{"ok": true}` (plain JSON).

### 3) Decision logic (runs on the ESP32)
- Sensor model: 5 features → logistic regression → p_normal, p_leak, p_fire_sensor.
- Camera late fusion: if `cv_fresh`, `p_fire = 1 − (1 − p_fire_sensor) × (1 − 0.5 × cv)`, else `p_fire = p_fire_sensor`. The camera alone can reach WARNING, never ALARM.
- Candidate level: **ALARM** if p_fire ≥ 0.6 · **WARNING** if p_leak ≥ 0.5 or p_fire ≥ 0.3 · else **NORMAL**.
- Go up after 2 ticks in a row (1 s). Go down from WARNING after 20 calm ticks (10 s). **ALARM stays latched until an authorized `reset`.**
- A gas leak that stays WARNING for 10 s escalates to ALARM (cause `gas_leak`).
- Response budget: window fills in ≤ 5 s + 1 s confirmation → alarm in under 10 s (target ≤ 20 s).
- Link lost (no valid reply for 3 s): board keeps deciding alone, `cv` = 0, valve closes (safe state).
